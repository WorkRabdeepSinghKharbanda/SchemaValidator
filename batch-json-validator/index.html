Batch JSON Validator

Validate every record in an array independently against one schema — free, in your browser, with a per-record pass/fail table.

Validate your batch now

Why validate a whole array at once?

A single validation run tells you whether one JSON object matches a schema. A batch of imported records, API responses, or seed data needs the same check applied to every item — and a way to see which specific records failed, not just an aggregate pass/fail for the whole file.

How it works

  1. Open Schema Validator and turn on batch mode.
  2. Paste or upload a top-level JSON array of records.
  3. Paste the JSON Schema each record should match.
  4. Get a per-record pass/fail table with a progress bar — export all results, failing records only, or as CSV.

What a batch run looks like, with an example

Given this array and schema:

[
  { "sku": "A-100", "price": 19.99 },
  { "sku": "A-101", "price": "19.99" },
  { "sku": "A-102" }
]
{
  "type": "object",
  "properties": {
    "sku": { "type": "string" },
    "price": { "type": "number" }
  },
  "required": ["sku", "price"]
}

the result table shows row 1 passing, row 2 failing (price is a string, not a number — a common artifact of data that passed through CSV at some point, where every value is a string), and row 3 failing (missing price entirely). Each failing row's errors are the same ajv error objects single-record mode produces — same messages, same instancePath — just scoped to that one array index instead of the whole document.

Reading the results: three export options

  • Export JSON — every row's result (pass or fail, with error details) as one JSON file, useful for feeding into another script or keeping an audit trail of a specific validation run.
  • Export failing only — the same export, pre-filtered to just the records that didn't pass. This is the one most people want after a real import: you already know the passing records are fine, you just need the broken ones to go fix at the source.
  • Export CSV — the batch results reserialized as CSV (via the same serialize() path the format converter uses), useful for pasting into a spreadsheet to triage failures with non-technical teammates.

Common errors and how to read them

Every single record fails with the same error. Before assuming the schema is wrong, check whether the top-level pasted value is actually an array — if you pasted a single object instead of an array of them, batch mode has nothing to iterate, and depending on how the data is structured you may see one misleading result instead of the per-record breakdown you expected. Wrap a single record in [ ] to batch-validate just one.

The progress bar finishes instantly with zero rows shown. An empty array ([]) is valid input with nothing to validate — this isn't an error, there's just nothing to report on. Check the array actually has elements.

A record fails that looks identical to one that passed. Check for a type mismatch invisible at a glance — a trailing space making a "number-looking" string not parse as intended, or inconsistent key casing between records from different data sources merged into one array. The per-row error list shows the exact instancePath and keyword that failed, same as single-record mode, so expand the failing row rather than comparing two rows by eye.

Leaving the schema pane empty shows every record as passing. This is intentional, not a bug — an empty schema is treated as trivially valid in both batch and single-record mode (a syntax-only check), so if you expected real validation and got all-green, confirm the schema pane actually has your schema in it.

When batch mode is the right tool

This is built for checking an already-assembled array — a paginated API response flattened into one JSON file, a seed-data fixture for tests, an export from another system before importing it into yours. It's not a bulk-upload or streaming validator for files too large to paste into a browser editor comfortably; for genuinely large datasets, consider validating a representative sample here first to confirm the schema is right, then applying the same schema via the "Copy as Node.js/Python snippet" feature in a script that can stream the full file.

A closely related but distinct need: validating CSV data specifically (each row as a record) is covered by the dedicated CSV validator page — batch mode here works with CSV too (any of the five supported formats, loaded as an array), but that page focuses on CSV's specific quirks (type coercion, since every CSV cell parses as a string).

Frequently asked questions

What if the schema pane is empty?

Batch mode treats an empty schema as trivially valid, same as single-record mode — every record passes a syntax-only check.

Can I export just the failing records?

Yes, an "Export failing only" button downloads just the invalid ones.

Does this work for YAML/CSV arrays too?

Yes — batch mode works with any of the five supported data formats, not just JSON.

Can I export the results as CSV instead of JSON?

Yes, an "Export CSV" button reserializes the batch results table as CSV, useful for triaging failures in a spreadsheet.

What happens if I paste a single object instead of an array?

Batch mode expects a top-level array — wrap a single record in square brackets ([ ]) if you want to batch-validate just one record, or turn off batch mode to validate it directly.

Does each failing record show the same error detail as single-record validation?

Yes — the same ajv error objects (message, instancePath, keyword) per record, just scoped to that array index instead of the whole document.

Is there a limit on how many records I can batch-validate?

No hard limit imposed by the tool itself, but this runs entirely in the browser — a very large array (tens of thousands of records) will be slower than a server-side batch job, since there's no streaming or pagination.
