Common JSON Schema mistakes a linter catches (that validation won't)

A schema that compiles fine can still be quietly wrong in ways that only surface later, as a confusing bug report.

A required field that's never declared

If required lists a property name that isn't in properties, the schema is syntactically fine — and every single record will fail, because that field can never be satisfied the way you intended. This is the single most useful thing a schema linter can flag, because it's invisible until you actually run validation against real data and wonder why nothing passes.

Unset additionalProperties

Leaving additionalProperties unset means any object schema silently accepts extra, unexpected fields — including a typo'd version of a real field name, which validation will never catch because as far as ajv is concerned, an extra field is just... extra.

A single-value enum

An enum with exactly one allowed value is usually a sign the field should be a const instead — functionally similar, but clearer about intent to the next person reading the schema.
