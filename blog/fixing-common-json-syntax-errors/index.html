Fixing common JSON syntax errors: trailing commas, single quotes, unquoted keys

JSON is strict on purpose, but the mistakes that break it are almost always the same handful, every time.

Trailing commas

JavaScript object literals tolerate a trailing comma before a closing } or ]; strict JSON does not. Copy-pasting from JS source (or from an editor that auto-formats JS-style) is the most common way a trailing comma sneaks into otherwise-valid JSON.

Single quotes instead of double

JSON requires double-quoted strings; single quotes are a JavaScript-ism that looks identical at a glance but fails a strict parser immediately. This is especially common when JSON is typed by hand rather than generated by a serializer.

Unquoted object keys

{ name: "value" } is valid JavaScript, not valid JSON — keys need quotes too. Same root cause as the single-quote issue: JS and JSON look almost identical but aren't interchangeable.

Fixing these without hunting by hand

All three are mechanical, predictable transformations — which is exactly the kind of thing worth automating rather than scanning a large file character by character for the one comma that broke everything.
