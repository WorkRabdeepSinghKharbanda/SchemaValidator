Generating field documentation from a JSON Schema for non-engineers

A JSON Schema is a great contract for a validator. It's a terrible thing to hand a product manager and ask them to read.

The audience problem

A schema is written for a validation engine, not a person — nested properties/items/$ref structure that's perfectly parseable by ajv is genuinely hard to skim for someone checking "does this API accept a phone number field, and is it required." Handing over the raw schema either gets ignored or triggers a round of clarifying questions that a readable doc would have answered up front.

What a field doc needs that a schema doesn't have

Plain field names, a plain-English type description, whether it's required, and any constraints worth knowing (an enum's allowed values, a format) — laid out as a table, not a nested tree structure.

Keeping it in sync automatically

The same problem that affects hand-written TypeScript types affects hand-written docs: they drift from the schema the moment either one changes without the other being updated. Generating the doc directly from the current schema means it can't describe a field that no longer exists.
