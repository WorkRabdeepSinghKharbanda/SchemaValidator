How to generate a JSON Schema from an example payload

Writing a schema from scratch for data that already exists is backwards — infer a draft from the data, then refine it.

Start from the data, not a blank schema

If you already have a real API response, config file, or database export, its shape is right there. Schema inference reads that shape — property names, types, nesting — and produces a draft schema, which is almost always faster than typing every field by hand, even if you end up tightening it afterward.

What inference gets right, and what it can't guess

Inference can see types and structure directly from your sample. It can't guess intent: whether a field should be required, whether a string should have a pattern, or whether a number needs a minimum. Treat the generated schema as a first draft, not a final one — tighten constraints based on what you actually know about the data, not just what one sample happened to look like.

A common trap: arrays

An array's shape is usually inferred from its first element only. If your array can contain items with genuinely different shapes, review the generated items schema by hand rather than trusting it blindly.
