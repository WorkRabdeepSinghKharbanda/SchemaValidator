Handling multi-file JSON Schemas with $ref

A schema referencing another schema by $ref is only as validate-able as your tooling's ability to actually resolve it.

Why schemas get split across files at all

A shared "Address" or "Money" shape used by a dozen different schemas shouldn't be copy-pasted a dozen times — $ref lets one schema point at another so common shapes are defined once. This is exactly how OpenAPI specs structure components.schemas internally, and it's just as useful in plain multi-file JSON Schema.

What has to happen for a $ref to actually resolve

A validator needs every referenced schema registered before it compiles the schema that points at it — an unregistered $ref id fails at compile time, not with a helpful "file not found" message pointing at the actual problem, usually just a confusing internal ajv error.

Testing this without a build pipeline

If your validator supports uploading multiple schema files and registering them as references, you can test the exact multi-file setup you'll deploy with, without needing a bundler step that inlines every $ref into one file first.

Try it

Schema Validator's reference-schema panel lets you upload multiple schema files and resolves $refs between them directly in the browser — and the OpenAPI import does this automatically for an entire spec's components.schemas.
