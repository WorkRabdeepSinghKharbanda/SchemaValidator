How the JSON Schema `pattern` keyword actually works

`pattern` is just a regular expression tested against a string value — but a few gotchas trip people up regularly.

It's unanchored by default

Unlike some regex contexts, JSON Schema's pattern matches if the regex matches anywhere in the string, not the whole string, unless you anchor it yourself with ^ and $. A pattern like [0-9]+ without anchors will happily match "abc123def", which is rarely what anyone intended.

It uses ECMA-262 regex syntax

JSON Schema's pattern is defined against the ECMA 262 regular expression dialect — the same one JavaScript uses — not PCRE or POSIX. Named capture groups, lookbehind, and other dialect-specific features may behave differently (or not be supported) depending on the validator's regex engine.

Debugging a pattern mismatch

The frustrating part of a pattern validation failure is that the error tells you the value didn't match, not why. Testing the exact pattern string against candidate values, live, next to the actual validation error, closes that gap immediately instead of round-tripping through a separate regex tool.
