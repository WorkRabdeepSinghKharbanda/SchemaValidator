Validating JSON config files in CI without a server

Design the schema interactively in a browser, then run the exact same check as a pipeline step.

The problem with "it looked fine when I checked it manually"

A schema that's only ever run by hand in a browser tab doesn't catch the config file someone edits three weeks later. You want the same check to run automatically on every pull request — but that usually means writing an ajv/jsonschema script from scratch, or standing up an API endpoint just to run a validation call. Neither should be necessary for something this small.

Design once, export a script

Schema Validator's schema pane has a "Copy as Node.js snippet" / "Copy as Python snippet" action in its "⋯" menu. It generates a small, self-contained script — ajv for Node, jsonschema for Python — with your exact schema and draft version already baked in. Drop it into your repo and point it at a config file path as an argument.

Wiring it into CI

# .github/workflows/validate-config.yml (Node example)
- name: Validate config against schema
  run: node scripts/validate-config.js config/production.json

No API call, no server round-trip — it's the same logic that already validated the file in your browser, just running as a local script. Commit the generated script alongside the schema it was generated from, and regenerate it (paste the updated schema, copy again) whenever the schema changes.
