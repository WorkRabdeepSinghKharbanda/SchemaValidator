CSV Schema Validator

Validate every row of a CSV export against a JSON Schema — free, in your browser, with a per-row pass/fail table so you can find bad records fast.

Validate your CSV now

Why validate a CSV against a JSON Schema?

CSV exports from a database, a form tool, or another system routinely have missing fields, wrong types (a price column with a stray currency symbol), or values outside an expected set — and CSV itself has no way to express or check those rules. A header row tells you the column names, nothing about whether age should be a positive integer or status should only ever be "active", "paused", or "cancelled". A JSON Schema expresses exactly that, and batch mode runs it against every row in one pass instead of you scrolling a spreadsheet looking for the row that breaks a downstream import.

How it works

  1. Open Schema Validator and turn on batch mode.
  2. Switch the data pane's format tab to CSV and paste or upload your file.
  3. Paste the JSON Schema each row should match.
  4. Get a per-row pass/fail table with a progress bar — export all results, failing rows only, or as CSV.

CSV has no native type system, so every cell parses as a string first. The parser (Papa Parse under the hood, via Schema Validator's lib/parse.ts) converts each row into a plain object keyed by header name before handing it to batch mode — so a schema written against that row shape works exactly like it would against one record of parsed JSON. For example, with this CSV: 

name,age,email
Dana Lee,34,dana@example.com
Priya K,twenty-nine,priya@example.com

and this schema:

{
  "type": "object",
  "properties": {
    "name": { "type": "string" },
    "age": { "type": "integer", "minimum": 0 },
    "email": { "type": "string", "format": "email" }
  },
  "required": ["name", "age", "email"]
}

row 1 passes, row 2 fails on age — Papa Parse's dynamic typing leaves "twenty-nine" as a string, which fails "type": "integer" rather than silently coercing to a number. That's the per-row table doing its job: it surfaces exactly which records a strict downstream system (a database import, an API bulk endpoint) would also reject.

Common errors and how to read them

  • A numeric-looking column fails type: integer. CSV values are strings unless Papa Parse's type inference recognizes them as numbers — a stray space, a currency symbol ("$34"), or a thousands separator ("1,200") all stay strings and fail. Clean the column before validating, or loosen the schema to "type": ["integer", "string"] if the mixed shape is expected.
  • Every row fails the same property with "must have required property". Almost always a header mismatch — a column named e-mail in the file against a schema that requires email. Check the header row's exact spelling and casing first; batch mode validates by property name, not column position.
  • Rows shift after a certain line, failing on unrelated properties. An unescaped comma or newline inside a quoted field earlier in the file. CSV requires a field containing a comma to be wrapped in double quotes; one missing quote can misalign every row after it. Re-export the file with proper quoting rather than hand-editing the CSV.
  • The whole batch run shows "0 rows" or errors before any row-level results appear. A parse-level failure, usually a malformed header row or a file that isn't actually CSV (tab-separated, semicolon-separated). Check the raw file first — batch mode can't validate rows it couldn't parse out.

Frequently asked questions

Can I validate a CSV file row by row?

Yes — batch mode validates each row independently and shows a pass/fail table with a progress bar.

Can I export just the failing rows?

Yes, the batch table has an "Export failing only" button, plus full JSON and CSV export of all results.

Is my CSV uploaded anywhere?

No — parsing and validation both run in your browser.

Does this check CSV file encoding (e.g. is it valid UTF-8)?

No — this validates the parsed rows' structure and values against a JSON Schema, not the raw file's byte encoding. If a CSV fails to parse at all because of an encoding issue, that will show as a parse error, but detecting/fixing encoding problems specifically isn't what this tool does.

Is there a CSV validator library for Python, JavaScript, or a GitHub Action?

Not from this project — it's a browser tool, not a published library. If you need the same check to run outside the browser (CI, a script, a scheduled job), use the schema pane's "⋯" menu → "Copy as Node.js snippet" or "Copy as Python snippet". Each generates a small self-contained script (ajv for Node, jsonschema for Python) templated with your current schema, which you can drop into a CI step or a GitHub Action yourself — it just won't loop over CSV rows for you; that part is a few lines of csv/papaparse glue in whichever language you pick.

Does it matter what order the CSV columns are in?

No. Each row is parsed into an object keyed by its header name, and schema validation checks properties by name, not position — reordering columns in the file doesn't change which rows pass or fail.

Can I validate a CSV with nested or repeated fields, like a JSON column inside a cell?

A cell's own content is validated as a plain string by default. If one column holds JSON text (e.g. an embedded array or object serialized into a single cell), write the schema for that property as "type": "string" — this tool doesn't parse nested JSON out of a CSV cell automatically.

What happens to blank cells and empty rows?

A blank cell in an otherwise valid row parses as an empty string, which will fail a schema that requires a non-empty value, a specific format, or a numeric type — treat a blank cell as "present but invalid," not "missing," unless you've made that property optional. Fully empty rows are skipped before they reach the schema.

Working with a single record instead of a batch? Schema Validator also supports JSON, YAML, TOML, and XML in single-record mode. For validating many JSON records at once instead of CSV rows, see the batch JSON validator.
