JSON Repair

Auto-fix the JSON slips that break strict parsers — trailing commas, single quotes, unquoted keys — free, in your browser, one click.

Repair your JSON now

Why auto-fix instead of hunting for the broken character by hand?

Hand-written or copy-pasted JSON (from a log line, a chat message, a loosely-typed config) often has small syntax slips that a strict parser rejects outright: a trailing comma, single quotes instead of double, an unquoted key. Auto-fix repairs the common cases in one click instead of you scanning character by character.

This comes up most with JSON that was never meant to be strict in the first place: a config file someone wrote by hand and formatted like a JavaScript object literal, a log line that truncated mid-object, or JSON copy-pasted out of a chat tool that silently "smart-quoted" the double quotes into curly ones. None of these are safe to run through JSON.parse directly, and manually finding the one bad character in a large pasted blob is slow and error-prone — a missing bracket three levels deep is easy to miss by eye.

How it works

  1. Open Schema Validator and paste JSON with a syntax error into the data pane.
  2. If it's a plain parse error, an "Auto-fix" button appears.
  3. Click it — trailing commas, single quotes, unquoted keys, and some structural gaps (a missing comma or bracket) are repaired automatically.
  4. Didn't want the change? A one-click "Undo" on the success toast reverts it.

Auto-fix wraps the jsonrepair library, dynamic-imported only when you click the button (so it never adds weight to the page for people who don't need it). It's worth being precise about its real scope, since it does more than the three cosmetic fixes it's best known for. Cosmetic fixes: 

// before
{ name: 'Dana', active: true, }

// after
{ "name": "Dana", "active": true }

Unquoted keys, single quotes, and the trailing comma are all repaired in one pass. But it also handles some structural gaps that aren't purely cosmetic — a missing comma between fields, or a missing closing bracket:

// before (missing comma, missing closing brace)
{ "name": "Dana" "age": 34

// after
{ "name": "Dana", "age": 34 }

What it does not do is fix logical/semantic errors — a value that parses fine as JSON but is wrong in meaning. {"age": "thirty-four"} is syntactically valid JSON; auto-fix won't convert the string to a number, infer that age should be numeric, or know that -5 is an invalid age. That's a schema-validation problem, not a syntax-repair one — pair auto-fix with the JSON validator's type checks, or the type-coercion quick-fix that appears on a type error once the JSON itself parses.

Common errors and how to read them

  • Auto-fix button doesn't appear at all. It's only offered for JSON data with a plain parse error — if the format tab is set to YAML/TOML/XML/CSV, or the pane already has schema-validation errors (meaning the JSON itself parsed successfully), there's nothing for it to fix.
  • Auto-fix ran but the result still fails validation. Expected if the original problem was semantic, not syntactic — auto-fix got the text parsing again, but a wrong value (wrong type, out of range, missing required field) is a separate, unrelated failure that schema validation will still catch.
  • The fixed JSON looks different from what you expected. jsonrepair makes a best-effort structural guess when brackets or commas are missing — for deeply malformed input with multiple overlapping issues, its guess about where a missing } belongs may not match your intent. Check the diff before trusting it blindly on anything non-trivial, or use Undo and fix the ambiguous section by hand.
  • Auto-fix silently did nothing after a long paste. The feature snapshots the data text before running and re-checks it hasn't changed when the fix comes back — if you kept typing while it was mid-fix, a changed snapshot is discarded rather than overwriting your newer edit. Click Auto-fix again once you've stopped typing.
  • Repaired JSON parses but still looks "wrong" structurally, like an extra nested object. When the input has more than one plausible structural reading — for example two consecutive objects with no separator at all, rather than a single clearly missing comma — the library has to guess which fix produces valid JSON, and its guess optimizes for "something that parses," not for matching exactly what you originally meant. The messier the input, the more worth a manual check after auto-fix runs.

Frequently asked questions

What kinds of errors does it fix?

The common syntax slips — trailing commas, single-quoted strings, unquoted object keys — plus some structural gaps like a missing comma or missing closing bracket. It can't fix logical errors (syntactically fine, semantically wrong).

Does it work on schema too, or just data?

It's offered for JSON data with a plain parse error; the same JSONC-tolerant parser also accepts comments and trailing commas in both panes without needing a fix at all.

Can I undo an auto-fix?

Yes, a one-click Undo appears on the success toast right after.

Can it fix JSON that's missing a comma or a closing bracket, not just quote style?

Yes — this is a common misconception about jsonrepair-style tools. Beyond the three cosmetic fixes (trailing commas, single quotes, unquoted keys), it also handles some structural gaps like a missing comma between fields or a missing closing bracket/brace. It still can't fix a value that's syntactically fine but semantically wrong, like a string where a number was meant.

Does this repair JSON for free, with no limits?

Yes — it's free, runs entirely in your browser, and nothing is uploaded. There's no record limit or paywall on the repair itself; it operates on whatever you paste into the data pane.

Is there a JSON repair API or command-line tool I can call from a script?

Not from this project — no backend or CLI is built here by design, intentionally, since that would need a server or a packaging step outside this browser app. If you need the same repair logic outside the browser, jsonrepair itself (the library this tool wraps) is a standalone npm package you can install and call directly in Node.
