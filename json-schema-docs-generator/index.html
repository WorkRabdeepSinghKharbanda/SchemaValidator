Why generate docs from a schema instead of writing them separately?

A schema and a hand-written field-reference doc drift apart the same way a schema and a hand-written TypeScript type do. Generating the doc directly from the schema means it can never describe a field that no longer exists, or miss one that was just added — and it's readable by someone who's never seen raw JSON Schema.

How it works

  1. Open Schema Validator and paste your JSON Schema.
  2. Use the schema pane's "⋯" menu → "Export field docs".
  3. Choose Markdown (for a repo/wiki) or PDF (a branded table, ready to share as-is).
  4. Send it to whoever needs a plain-English reference, not the raw schema.

Frequently asked questions

Does the PDF look like a plain generic report?

No — it shares the app's own dark theme and brand mark, not a plain white default PDF layout.

Does this replace the Markdown export?

No, both exist side by side — pick whichever fits where you're sharing it.

Does it cover nested fields?

Yes, the field table walks the schema's structure, not just its flat top level.
