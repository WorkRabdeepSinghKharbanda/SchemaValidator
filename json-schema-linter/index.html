JSON Schema Linter

Catch common JSON Schema smells — before they cause a confusing validation bug — free, in your browser.

Lint your schema now

Why lint a schema, if it already validates fine?

A schema can be syntactically valid and still have real problems: a required field that's never declared in properties (which can never pass), an unset additionalProperties that silently accepts typo'd field names, or a single-value enum that should just be a const. These aren't validation errors — they're the kind of mistake that only shows up later, as a confusing bug report.

How it works

  1. Open Schema Validator and paste your JSON Schema.
  2. Below the schema summary, expand the "Schema lint hints" section.
  3. Review each hint — unset additionalProperties, undeclared required fields, single-value enums.
  4. Fix what applies; hints are suggestions, not hard errors.

Frequently asked questions

Does linting replace validation?

No — it's a separate, best-practice pass alongside normal ajv validation, not a substitute for it.

Does it check nested schemas?

Yes, recursing into nested properties and array items (depth-capped), skipping $ref nodes rather than guessing at what they resolve to.

Can a lint hint ever be wrong?

The checks are deliberately conservative — only flagging things that are unambiguously worth a second look, not guessing at intent.
