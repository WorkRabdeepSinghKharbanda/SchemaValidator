Why test a regex inside the validator instead of a separate regex tool?

A pattern-keyword validation error tells you a value didn't match, but not why — testing the actual schema pattern against candidate values in a separate regex tool means re-copying the pattern by hand and hoping you copied it exactly. Testing it inline, against the same pattern string ajv just used, removes that step.

How it works

  1. Open Schema Validator, validate data with a pattern constraint in the schema.
  2. On a pattern-mismatch error, click "Test pattern" to expand an inline input.
  3. Type candidate values and see a live match/no-match against the schema's actual pattern.
  4. Adjust your data (or the schema's pattern) based on what you see.

Frequently asked questions

Does it use the exact pattern from my schema?

Yes — the same pattern string ajv compiled, re-compiled independently with new RegExp for the live test.

What if the pattern isn't valid JS regex syntax?

The tester returns no match rather than throwing, so an edge-case pattern doesn't break the page.

Is this only for pattern errors?

Yes, it's offered specifically alongside a pattern-keyword validation error in the error list.
