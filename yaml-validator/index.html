Why validate YAML against a JSON Schema?

YAML is the default format for Kubernetes manifests, GitHub Actions workflows, OpenAPI specs, and countless app config files — but YAML's own syntax rules won't catch a missing required field, a wrong type, or a typo'd enum value. A JSON Schema catches exactly those mistakes, and the same schema can validate both your YAML and JSON representations of the same data.

How it works

  1. Open Schema Validator and switch the data pane's format tab to YAML.
  2. Paste or upload your JSON Schema in the schema pane (JSON Schema is always authored as JSON, even when validating YAML data).
  3. Paste or upload your YAML file in the data pane.
  4. Errors appear inline with an approximate line number, plus a plain-English explanation of what's wrong.

Frequently asked questions

Can I validate a YAML file against a JSON Schema?

Yes — pick the YAML tab, paste your schema, and paste or upload your YAML file. Validation runs the same ajv engine used for JSON.

Does my YAML get uploaded to a server?

No. Everything runs client-side in your browser. Nothing you paste or upload is sent to a server.

Which JSON Schema drafts are supported?

Draft-07, 2019-09, and 2020-12 — switchable, or auto-detected from the schema's $schema field.

Need a different format? Schema Validator also supports JSON, TOML, XML, and CSV data — same schema, same engine.
